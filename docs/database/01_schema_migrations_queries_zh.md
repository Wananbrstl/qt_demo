# SQLite 模式、迁移与查询

## 模式意图

`devices` 是父实体，遥测、命令和告警引用稳定设备 ID。遥测复合索引服务于主要查询：

```sql
WHERE device_id = ? AND captured_at_ms BETWEEN ? AND ?
ORDER BY captured_at_ms DESC
```

索引顺序来自过滤和排序形状，而不是给每一列盲目加索引。索引会占空间并增加写放大，必须用查询计划和真实数据分布验证。

## 迁移纪律

迁移 001 建立基线并记录版本。数据一旦共享，禁止修改已应用迁移；应新增 `002_...sql`，在事务中执行，成功后才推进 `schema_version`。启动前应验证当前版本、迁移连续性和数据库是否比程序支持版本更新。

## 预编译语句

值与 SQL 分开绑定，既避免引号错误和 SQL 注入，也允许驱动复用语句计划。表名、列名等标识符不能通过普通参数绑定，必须来自受控白名单。

## 分页

教学版使用 LIMIT/OFFSET。大历史数据应使用 `(captured_at_ms, id)` 键集分页，避免 offset 越大扫描越多。排序键必须唯一且稳定，否则相同时间戳可能造成遗漏或重复。

## 实验

- 为遥测质量字段新增迁移，验证旧库升级和全新建库结果一致。
- 删除复合索引前后运行 `EXPLAIN QUERY PLAN` 并记录 P50/P95/P99。
- 实现确定性键集分页，在并发插入时验证无重复、无遗漏。
- 构造比程序更新的 schema version，确认程序拒绝写入而不是冒险降级。
