# 连接状态、心跳与重连

## 状态流

```text
Disconnected → Connecting → Handshaking → Online
                      ↓                     ↓
                 Reconnecting ← Degraded ← timeout
```

状态必须显式存在，UI 动作可用性和诊断信息不应从分散的 socket 标志猜测。每个事件在每个状态下都应有明确定义：转换、忽略或报告协议错误。

## 握手

TCP connected 只表示传输连接建立，不代表应用协议兼容。收到 `HelloAck` 后才进入 Online。能力协商、认证、设备身份和版本选择都应位于握手阶段。

## 心跳

客户端每 2 秒发送心跳，并检查距任意入站帧的时间。静默 6 秒进入 degraded 并触发重连。真实系统应按设备和网络特征配置阈值，并使用单调时钟测量间隔，避免系统时间调整影响超时。

## 重连

延迟指数增长并加入随机抖动，防止网络恢复后数百设备同步重连形成惊群。用户主动断开会设置 `shutdownRequested_`，禁止自动重连。延迟应有上限，成功在线一段稳定期后再重置退避次数。

## 实验

- 在模拟器注入 30% 心跳丢失、延迟和乱序观测。
- 增加最大尝试或长期离线策略。
- 注入虚拟时钟，使测试无需等待真实秒数。
- 为命令定义是否可安全重试以及幂等规则。
- 同时启动 100 个客户端，比较无抖动、全抖动和 decorrelated jitter 的重连分布。

验收：网络恢复时连接尝试不会形成尖峰；主动断开绝不重连；状态转换日志包含原因、连接代次和退避时间。
