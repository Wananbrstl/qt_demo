# 故障排查案例

## 案例 1：断点无法绑定

确认所选二进制确实包含目标源码、属于 Debug 构建且 GDB 没有等待 debuginfod。工程调试配置已禁用 debuginfod。依次检查 `file`、`.debug_info`、`info sources`、`info sharedlibrary` 和 `info line`，用证据区分“模块未装载”“路径不一致”和“该行无机器码”。

## 案例 2：QObject 定时器线程警告

出现 “Timers cannot be started from another thread” 时，检查定时器的创建线程。worker 的定时器必须在 `moveToThread` 之后创建，不能在 GUI 线程执行的构造函数中提前创建。记录对象 `thread()` 和 `QThread::currentThread()`，不要仅凭调用栈猜测。

## 案例 3：历史查询导致 UI 卡顿

确认控件没有直接调用 `QSqlQuery`。分别记录排队请求、worker 执行和结果交付耗时。超大查询应使用独立只读连接、键集分页或分批流式交付，禁止一次返回数百万行。验收时同时观察 GUI 事件循环延迟和数据库 P99 查询延迟。

## 案例 4：部分 TCP 消息“消失”

不要把 `readyRead` 次数当作帧数。记录解码器缓存字节数、声明帧长、序列号、解析结果和错误，执行所有拆分边界测试。若序列号缺失，还要区分发送端未发送、网络连接重建、接收端丢弃和业务去重。

## 案例 5：停靠布局不可用

使用 **View → Reset Dock Layout**。修改 dock 的 `objectName` 或布局结构时递增 `saveState` 版本，让不兼容状态被拒绝。多屏环境还应检查恢复后的窗口矩形是否与任一可用屏幕相交。

## 案例 6：数据库偶发 busy/locked

记录事务开始、提交、回滚、耗时和队列深度。确认没有跨线程复用连接，长查询是否占据同一连接，以及 WAL checkpoint 是否长期受读事务阻塞。不要通过无限增加 `busy_timeout` 掩盖长事务。

## 案例 7：断线恢复后命令重复执行

为每条命令记录稳定请求 ID、发送次数、确认状态和设备端执行结果。判断命令是否幂等；非幂等动作必须使用设备端去重表或查询执行状态，不能在超时后无条件重发。
